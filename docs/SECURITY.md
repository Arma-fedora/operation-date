# Безопасность и данные

Приложение личное и романтическое, но обращается с реальным Telegram-аккаунтом и сохраняет ответ. Здесь описано, что именно происходит с данными, от чего защищает код и что остаётся на стороне инфраструктуры.

## 1. Какие данные сохраняются

В Supabase:

- `sessions`: Telegram user ID, username, имя, фамилия, язык, текущий экран, завершённые экраны, версия клиента, время активности, SHA-256 от `initData`;
- `user_progress`: снимок прогресса (экраны, улики, пазлы, секреты, испытания, маршрут, аудио-настройки);
- `puzzle_results`, `discovered_secrets`, `date_preferences`: те же данные в разложенном виде;
- `final_responses`: тип ответа (`yes`/`other_date`/`discuss`), дата, время, сообщение до 1000 символов, сценарий, статус доставки, ID сообщения бота, снимок прогресса.

В браузере:

- Zustand + localStorage (`operation-date-v1`): прогресс, финальный ответ, настройки звука, тема;
- тема отдельно: `operation-date-theme`.

Не собираются: геолокация, контакты, переписки, номера телефонов, email, данные платёжных карт, содержимое буфера обмена. Приложение не читает другие чаты Telegram.

## 2. Модель доступа

```text
Telegram WebView
  └─ initData (подпись бота)
       └─ Supabase Edge Function game-api
            ├─ проверка HMAC по TELEGRAM_BOT_TOKEN
            ├─ проверка auth_date
            └─ service-role доступ к Postgres
```

- Клиент не имеет доступа к таблицам. `anon` key публичен, но RLS включён, а права у `anon`/`authenticated` отозваны.
- `service_role` key существует только в переменных Edge Function. Он никогда не попадает в JS-бандл.
- Каждый запрос `game-api` обязан содержать `initData`. Подпись проверяется по алгоритму Telegram: `HMAC-SHA256(WebAppData, bot_token)` → ключ, затем `HMAC-SHA256(secret_key, data_check_string)`.
- `auth_date` ограничен `INITDATA_MAX_AGE_SECONDS` (по умолчанию сутки). Слишком старые и «будущие» данные отвергаются.
- Сравнение подписи и webhook-секрета — побайтовое, без раннего выхода.
- `game-api` не доверяет полю `user` до проверки подписи.
- `telegram-webhook` требует заголовок `X-Telegram-Bot-Api-Secret-Token`. Без `TELEGRAM_WEBHOOK_SECRET` функция отказывается работать.

## 3. Что валидируется на сервере

`supabase/functions/_shared/sanitize.ts`:

- ограничивает общий размер снимка прогресса (140 КБ);
- проверяет допустимые экраны, ID пазлов, типы полей;
- обрезает строки, массивы, числа, флаги;
- проверяет дату `YYYY-MM-DD`, время `HH:MM`, длину сообщения, обязательность даты/сообщения для нужного типа ответа;
- отклоняет даты в прошлом и слишком далёком будущем;
- не принимает произвольный `finalResponse` из снимка прогресса — финальный ответ хранится отдельно и валидируется отдельно.

Клиентские ограничения (`maxLength`, `min`) — только UX. Сервер повторяет проверки.

## 4. XSS и инъекции

- React экранирует текст в интерфейсе.
- Сообщение боту собирается с `parse_mode: 'HTML'`, поэтому все пользовательские поля проходят через `escapeHtml` (`&`, `<`, `>`). Ссылки и разметка из сообщения не исполняются.
- SQL-запросы идут через Supabase SDK с параметризацией; строковая конкатенация в SQL отсутствует.
- `progress_snapshot` хранится как JSONB и не исполняется.
- Внешние ссылки в интерфейсе не строятся из пользовательского ввода.

## 5. Секреты

| Секрет | Где хранится | Что будет при утечке |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Supabase secrets, `.env.setup` локально | Посторонний сможет писать от имени бота и подделывать `initData`. Немедленно `/revoke` у BotFather. |
| `SUPABASE_SERVICE_ROLE_KEY` | Только Supabase | Полный доступ к базе в обход RLS. Ротируйте в Dashboard. |
| `TELEGRAM_WEBHOOK_SECRET` | Supabase + Telegram | Посторонний сможет имитировать обновления бота. Смените секрет и перерегистрируйте webhook. |
| `TELEGRAM_OWNER_CHAT_ID` | Supabase | Не секрет, но позволяет понять, куда уходят ответы. |
| `VITE_SUPABASE_ANON_KEY` | Публично | Ничего: таблицы закрыты, функция проверяет `initData`. |

Правила:

- не коммитьте `.env.local`, `.env.setup`;
- не вставляйте service-role key в переменные с префиксом `VITE_` — всё с `VITE_` попадает в браузер;
- после смены токена обновите Supabase secrets и webhook;
- для локальных экспериментов используйте отдельного бота.

## 6. Ограничения и остаточные риски

1. **Повтор `initData`.** Подпись подтверждает, что данные выдал Telegram, но не делает их одноразовыми. В пределах `INITDATA_MAX_AGE_SECONDS` валидный `initData` можно переиспользовать. Для личного приложения это приемлемо; для публичного добавьте серверный nonce/сессию и более короткий срок.
2. **Нет встроенного rate limiting.** Edge Function может вызывать любой, у кого есть anon key и валидный `initData`. Supabase имеет квоты, но не защищает от целенаправленного спама. При публичном запуске добавьте лимиты на уровне прокси/шлюза или отдельную таблицу лимитов.
3. **CORS открыт (`*`).** Это не даёт доступа к данным без `initData`, но позволяет вызывать функцию с любого origin. Если хотите ужесточить, ограничьте `Access-Control-Allow-Origin` доменом приложения.
4. **Any Telegram user.** Пока `TELEGRAM_ALLOWED_USER_IDS` пуст, открыть бота может любой, кто узнает ссылку. Для подарка задайте allowlist.
5. **Логи.** В коде нет логирования `initData`, токенов и текста ответа. Ошибки Supabase/Telegram могут содержать технические детали; доступ к логам должен быть только у владельца проекта.
6. **Локальное устройство.** localStorage не шифруется. Если устройство общее, прогресс и финальный ответ видны в браузере. Кнопка «Пройти заново» очищает локальную копию, но серверную строку нужно удалять SQL-запросом.
7. **Третьи стороны.** Telegram видит факт открытия Mini App; Supabase хранит данные; Netlify отдаёт статику; OpenStreetMap получает запросы тайлов. Шрифты собраны локально (`@fontsource`), внешние запросы к Google Fonts не выполняются; тайлы OSM при необходимости можно хостить самостоятельно.

## 7. Рекомендуемая настройка для личного запуска

- `TELEGRAM_ALLOWED_USER_IDS` — ID Александры и, при необходимости, ваш.
- HTTPS-only, собственный домен.
- `INITDATA_MAX_AGE_SECONDS=3600` или меньше, если не нужны долгие сессии.
- Владелец получает уведомления в личный чат; не добавляйте бота в группы.
- Регулярно проверяйте `supabase secrets list` и `getWebhookInfo`.
- После завершения истории удалите данные, если они больше не нужны:

```sql
delete from public.sessions where telegram_user_id = <id>;
```

## 8. Удаление и хранение

- Каскадное удаление: `sessions` → `user_progress`, `puzzle_results`, `discovered_secrets`, `date_preferences`, `final_responses`.
- Срок хранения не задан автоматически. Для личного проекта достаточно удалить строки вручную после финала.
- Резервные копии Supabase могут хранить удалённые строки в течение настроенного окна — это управляется тарифом и настройками проекта.

## 9. Что проверить перед публичным запуском

- [ ] RLS включён на всех таблицах, прямых грантов `anon`/`authenticated` нет.
- [ ] `supabase functions list` показывает обе функции.
- [ ] `TELEGRAM_WEBHOOK_SECRET` задан и совпадает с Telegram.
- [ ] `TELEGRAM_ALLOWED_USER_IDS` заполнен, если приложение не для всех.
- [ ] Токен бота не встречается в `dist/` и в git.
- [ ] В `dist/assets/*.js` нет `service_role`.
- [ ] Проверены логи функций на отсутствие сырых `initData`.
- [ ] Настроено удаление данных после завершения.

Это инженерная памятка, а не юридическая консультация. Для публичного продукта с персональными данными нужны отдельные политика конфиденциальности и оценка применимого законодательства.
